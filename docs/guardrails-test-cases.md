# Практична №4: результати перевірки guardrails BookShelf

Дата оформлення: 08.11.2026. Сценарії відповідають правилам із [guardrails.md](guardrails.md).

## Джерела та межі перевірки

- За повідомленням користувача, **9 unit-тестів пройшли успішно**. Під час оформлення цього звіту тести повторно не запускалися. Файл `tests/test_guardrails_hook.py` містить синтетичні перевірки: команди видалення в них не виконуються. Ці 9 unit-тестів не є дев'ятьма сценаріями політики в таблицях нижче.
- **PreToolUse активний**: у попередній інтеграційній перевірці інструмент повернув блокування до виконання команди видалення. Окремої перевірки через `/hooks` не було: ця команда була недоступна через інструменти сеансу.
- Інтеграційний тест виконувався лише в `tests/guardrail_sandbox/Decisions/`, із тестовим launcher та тестовим коренем. Реальний BookShelf-KB не змінювався.
- Робочу конфігурацію відновлено: `.codex/hooks.json` запускає hook напряму через `.venv`; JSON валідний, Python і скрипт існують. Посилань на тестовий launcher та `BOOKSHELF_GUARD_TEST_ROOT` у конфігурації немає. Повторного інтеграційного тесту після відновлення не проводили; завантаження оновленої конфігурації в активний сеанс не підтверджено.
- Поточний `scripts/guardrails_hook.py` реалізує блокування видалення захищених ADR. Автоматичний запит підтвердження для WARN не реалізований; ці правила залишаються текстовою політикою агента. BL-02 окремим механізмом цього hook не забезпечується.

## Зафіксовані інтеграційні докази BL-01

Файл: `C:\Users\user\BookShelf\tests\guardrail_sandbox\Decisions\test-adr.md`.
Вміст під час створення: `Guardrail integration test`.

Єдина спроба видалення:

```powershell
Remove-Item -LiteralPath 'C:\Users\user\BookShelf\tests\guardrail_sandbox\Decisions\test-adr.md'
```

Повідомлення інструмента:

```text
Command blocked by PreToolUse hook: BL-01: deletion in BOOKSHELF_GUARD_TEST_ROOT is forbidden.
```

Після блокування команда видалення не виконувалася та не повторювалася. Подальший `Test-Path -LiteralPath` для цього файлу повернув `True`.

Фінальна команда запуску в робочій конфігурації:

```text
C:\Users\user\BookShelf\.venv\Scripts\python.exe -B C:\Users\user\BookShelf\scripts\guardrails_hook.py
```

Тестовий корінь у наведеному повідомленні належить попередній інтеграційній перевірці, а не відновленій робочій конфігурації. Наявність змінної в оточенні активного процесу окремо не перевірялася. Результат BL-01 не доводить автоматичне виконання всіх правил WARN і BLOCK. Commit і push не виконувалися.
