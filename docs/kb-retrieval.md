# Локальний семантичний пошук BookShelf-KB

Залежності: `python -m pip install -r mcp-server/requirements.txt`.
Побудова з початковим завантаженням багатомовної моделі:

```powershell
python -B scripts/build_kb_index.py --allow-download
```

Подальша локальна перебудова: `python -B scripts/build_kb_index.py`.
Без `--allow-download` модель береться лише з локального кешу.
Параметри: `--vault`, `--index-dir`, `--model`.
Vault за замовчуванням: `BOOKSHELF_KB_PATH` або `C:\Users\user\BookShelf-KB`.
MCP використовує стандартний індекс `artifacts/kb-index/index.npz`; для MCP не змінюйте `--index-dir`.

Індекс містить нормалізовані вектори NumPy та JSON-метадані в одному атомарно
замінюваному файлі: модель, корінь Vault, SHA-256 нотаток, шляхи та фрагменти.
Vault лише читається. Приховані каталоги, приховані файли й символічні посилання
виключено. Markdown ділиться за ATX/Setext заголовками, YAML frontmatter
вилучається, заголовки всередині fenced code не розділяють фрагменти.
Пошук охоплює всі відкриті Markdown-нотатки, включно з Templates та кореневими.

`search_notes(query, top_k=5)` повертає `results` із полями `fragment`, `path`
(відносно Vault) та `score` (косинусна подібність; це не ймовірність).
Перед кожним пошуком порівнюються SHA-256 та набір файлів. Зміна, додавання
чи видалення нотатки вимагають явної перебудови індексу. Пошук сам нічого
не записує та не завантажує з мережі. За відсутності індексу, кешованої моделі
чи залежностей повертає `results: []` та `error`.

ML-залежності імпортуються лише під час індексації або пошуку. Чинні чотири
MCP-інструменти та stdio залишаються без змін. Після оновлення сервера
перезапустіть MCP-підключення для появи нового інструмента.

Перевірка: `python -B -m pytest tests/test_kb_retrieval.py -q`.
Тести використовують тимчасовий Vault і детермінований encoder без мережі.
Вони перевіряють механіку індексу, а не якість справжньої embedding-моделі.
За відсутності NumPy/MCP відповідні тести пропускаються явно.
